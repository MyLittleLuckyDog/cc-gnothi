# `/clear`

> Analysis basis: CC v2.1.162 bundle.js (AST extraction + Claude interpretation)
> Minimum version: v2.1.162

---

## Overview

`/clear` starts a new Claude Code session with an empty conversation context, discarding all in-memory messages from the current session while leaving the session file safely on disk so it can be recovered with `/resume`. It also supports the aliases `/reset` and `/new`, and accepts an optional `[name]` argument to label the new session.

## Input Branching

There are four distinct execution paths depending on optional name argument, backgrounded state, and session initialization needs. A Mermaid flowchart is used.

```mermaid
flowchart TD
    A["/clear [name] invoked"] --> B{Trim argument string}
    B --> C{Name argument provided?}
    C -- "Yes" --> D[Validate / normalize name via sessionNameParser]
    C -- "No" --> E[Use auto-generated session label]
    D --> F{Session currently backgrounded?\n(isBackgrounded check)}
    E --> F
    F -- "Yes (backgrounded)" --> G[Emit tengu_cache_eviction_hint\nEmit conversation_clear telemetry\nSkip full reset path]
    F -- "No (foreground)" --> H[Run fullClearAndReset:\nflush in-memory conversation\narchive current session file\nemit conversation_reset]
    G --> I[Initialize new blank session context\nbHA reset sequence]
    H --> I
    I --> J[Persist new session metadata\nregister with session store]
    J --> K[Return success / new session ready]
```

### Non-Interactive / Thin-Client Dispatch

Because `supportsNonInteractive: true` and `thinClientDispatch: "post-text"`, the command can execute in piped/headless mode. In that mode the handler still performs the full reset sequence but does not wait for interactive confirmation.

## Common Mistakes

1. **Confusing `/clear` with data deletion** — The previous session transcript is retained on disk; use `/resume` to return to it. Running `/clear` does not permanently erase history.
2. **Expecting MCP connections to be torn down** — `/clear` flushes MCP tool-call caches but does not disconnect active MCP server processes; they remain alive for the new session.
3. **Using `/clear` in headless scripts without the alias** — `/reset` and `/new` are fully equivalent; scripts may use any of the three names.
4. **Supplying a numeric name and expecting it to be treated as a session index** — Numeric `[name]` arguments are parsed with `parseInt` and stored as a label string, not as a positional session index.
5. **Assuming backgrounded sessions follow the same code path** — When `isBackgrounded` is `true`, the handler takes a lightweight path that skips the full cache-clear sequence; behaviour observed in a backgrounded daemon tab will differ from a foreground interactive session.
